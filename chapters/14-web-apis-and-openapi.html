MODULE 14 / Web development

Web APIs and OpenAPI

Design maintainable APIs, validation and documentation. This module is built around a practical workplace scenario rather than memorizing syntax.

By the end you can: Build POST /enrollments and GET /students/{id}/enrollments with DTOs and status codes.
Pass criteria: Handle invalid IDs, duplicate requests and never trust client-provided ownership data.

How to work through this module

  1. Read each concept; type the sample rather than simply copying it.
  2. Predict the output, run with dotnet run, and compare your prediction.
  3. Complete the guided modification, then the independent challenge without looking at hints.
  4. Debug failures, check edge cases, take the quizzes, and mark this module complete.

Laravel connection: C# uses explicit types and compiled projects. A C# method resembles a PHP method, ASP.NET routes serve a similar role to Laravel routes, EF Core parallels Eloquent conceptually, and dependency injection is built into ASP.NET Core.

GUIDED LESSON 14.1

RESTful resource design

Name resources with nouns, use status codes consistently and distinguish DTOs from EF entities. Define pagination for endpoints that could return large collections.

Step 1 · Read and predict

Before running the example, underline all new keywords. Write down the output you expect or the change you expect it to make.

C#
var app = WebApplication.Create();
var products = new[] { new ProductDto(1, "Notebook") };
app.MapGet("/api/products", () => Results.Ok(products));
app.MapGet("/api/products/{id:int}", (int id) =>
    products.FirstOrDefault(p => p.Id == id) is { } p
        ? Results.Ok(p) : Results.NotFound());
app.Run();
record ProductDto(int Id, string Name);
