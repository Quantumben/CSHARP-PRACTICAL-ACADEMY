Classes, Records, and Encapsulation

Model behavior and state with classes, records and properties. This module is built around a practical workplace scenario rather than memorizing syntax.

By the end you can: Model SKU, name, price and stock; restock and sell operations must preserve invariants.

GUIDED LESSON 5.1

Classes and objects

A class defines a reference type. Encapsulation keeps invariants inside the type; avoid publicly writable fields for important state.

Step 1 · Read and predict

Before running the example, underline all new keywords. Write down the output you expect or the change you expect it to make.

C#
public class BankAccount
{
    public decimal Balance { get; private set; }
    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        Balance += amount;
    }
}

GUIDED LESSON 5.3

Records and immutability

Records are useful for data-oriented models and value-based equality. with expressions create modified copies, which is useful for state updates.

Step 1 · Read and predict

Before running the example, underline all new keywords. Write down the output you expect or the change you expect it to make.

C#
public record Student(string Name, int Level);
var student = new Student("Ada", 200);
var promoted = student with { Level = 300 };
Console.WriteLine(promoted);

GUIDED LESSON 5.4

Properties and indexers

Properties expose controlled access. Auto-properties are concise; custom accessors are appropriate when an invariant must be enforced.

Step 1 · Read and predict

Before running the example, underline all new keywords. Write down the output you expect or the change you expect it to make.

C#
public class Temperature
{
    private double _celsius;
    public double Celsius
    {
        get => _celsius;
        set => _celsius = value >= -273.15 ? value : throw new ArgumentOutOfRangeException(nameof(value));
    }
}
